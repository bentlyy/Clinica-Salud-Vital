## CAMBIOS REALIZADOS EN ESTA SESIÓN
===========================================================

### 1. Seguridad: CSP para MUI (blank page fix)
  - Archivo: src/middlewares/security.middleware.ts
  - style-src agregó 'unsafe-inline' porque MUI injecta estilos inline
  - Sin esto la página queda en blanco (CSP bloquea estilos de MUI)

### 2. ErrorBoundary crash (clase componente, sin acceso a context)
  - Archivo: frontend/src/components/ErrorBoundary.jsx
  - ErrorBoundary es class component, NO tiene acceso al I18nContext
  - Fix: import directo de translations.js como fallback, usa this.context cuando
    está disponible pero no falla si es null
  - Pasa locale como prop desde App.jsx (que sí tiene contexto)

### 3. ML: demandModel entrenaba en cada request
  - Archivo: src/modules/ml/ml.service.ts
  - demandModel.trained nunca se marcaba como true cuando usaba el fallback
    statistical (sin TensorFlow)
  - Fix: marcar demandModel.trained = true después del fallback
  - Consecuencia: en Render sin TensorFlow, el entrenamiento se ejecutaba en
    CADA request a /demand, causando latencia de ~4 segundos

### 4. Multi-tenant: aislamiento en analytics
  - Archivo: src/modules/analytics/analytics.controller.ts
  - Se agregó resolveTenantId() que usa req.tenant_id
  - Superadmin puede pasar ?all=true para ver datos de todos los tenants
  - Archivo: src/modules/analytics/analytics.export.ts
  - Se filtró export Excel por tenant_id

### 5. Multi-tenant: doctor profile solo muestra doctores del tenant
  - Archivo: src/modules/doctor/doctor.service.ts
  - Se agregó WHERE tenant_id = ? en getDoctors()
  - Se agregó WHERE tenant_id = ? en getDoctorByUserId()
  - Fix para el form de crear booking (mostraba doctores de otros tenants)

### 6. Build: type errors en Render
  - Problema: @types/sanitize-html no instalado, Express 5 usa ParamsDictionary
    con valores string | string[] (NO solo string como Express 4)
  - Fix analytics controller: resolveTenantId usa req: any en vez de AuthRequest
  - Fix super-admin: parseInt(String(req.params.userId), 10) para convertir
    string|string[] a string

### 7. Fix: double pool release en refreshToken
  - Archivo: src/modules/auth/auth.service.ts
  - refreshToken() hacía client.release() en returns tempranos (líneas 213, 221,
    230) PERO el finally block (línea 264) también llamaba release()
  - El finally SIEMPRE se ejecuta incluso con return en try/catch
  - Fix: eliminar todos los client.release() manuales dentro del try

### 8. Fix: demand forecast error log sin mensaje
  - Archivo: src/modules/ml/ml.service.ts (línea 1238)
  - logger.error('[ML] Error saving demand forecast:', (err as Error).message)
  - El mensaje se pasaba como metadata (segundo argumento), no se veía en consola
  - Fix: logger.error('[ML] Error saving demand forecast: ${msg}', { stack })

### 9. Fix: heap warnings falsos en monitoreo
  - Archivo: src/middlewares/monitoring.middleware.ts
  - heapWarningThreshold = 0.85 se disparaba con heap pequeño (ej: 27MB/30MB = 90%)
  - En Render free tier (512MB), heap de 40MB no es crítico
  - Fix: agregar condición current.heapUsed > 200MB además del ratio

## ARQUITECTURA CLAVE
===========================================================

- Express 5: ParamsDictionary valores = string | string[] (cambio breaking!)
- pg pool: SIEMPRE usar finally { client.release() } sin releases manuales
- Multi-tenant: todas las queries deben incluir WHERE tenant_id = ?
  Los seeds deben incluir tenant_id en INSERTs
- Superadmin: role='superadmin' sin tenant_id, acceso global
- ML: modelos se entrenan bajo demanda (no hay background worker),
  usar lazyload para TensorFlow (import dinámico)
- Frontend: AuthContext loading=true inicial, ErrorBoundary no tiene
  acceso a React context (class component)
