Copia y pega este mensaje completo en tu próxima conversación con la IA. Cada fase contiene:

- **Objetivo**: qué se busca lograr

## FASE 1: Bugfixes críticos (día 1-2)

### 1.1 Refresh token no valida token_version

**Archivo:** `src/modules/auth/auth.service.ts`

**Problema:** `refreshToken()` no compara `user.token_version` con el del token. Después de cambiar contraseña, un refresh token robado sigue funcionando.

**Solución:** En la función `refreshToken`, después de obtener el usuario, agregar:

```typescript
// auth.service.ts ~line 306
const userResult = await client.query<User>('SELECT * FROM users WHERE id = $1 AND active = true', [tokenRecord.user_id]);
const user = userResult.rows[0];
if (!user) {
  await client.query('ROLLBACK');
  return null;
}

// ✨ AGREGAR:
const currentTokenVersion = user.token_version || 0;
// Leer token_version del refresh token (lo guardamos al crear)
const refreshTokenVersion = tokenRecord.token_version || 0;
if (currentTokenVersion !== refreshTokenVersion) {
  await client.query('UPDATE refresh_tokens SET revoked = true WHERE id = $1', [tokenRecord.id]);
  await client.query('COMMIT');
  return null;
}
```

Además, al crear el refresh token, guarda el `token_version` actual:
```typescript
// En generateRefreshToken ~line 75
await pool.query(
  'INSERT INTO refresh_tokens (user_id, token, expires_at, token_version) VALUES ($1, $2, $3, (SELECT COALESCE(token_version, 0) FROM users WHERE id = $4))',
  [userId, tokenHash, expiresAt, userId]
);
```

Y agregar columna `token_version` a `refresh_tokens`:
```sql
ALTER TABLE refresh_tokens ADD COLUMN IF NOT EXISTS token_version INTEGER DEFAULT 0;
```

### 1.2 RLS superadmin_bypass no funciona

**Archivos:** `db/init.sql`, `src/shared/db.ts`

**Problema:** La policy RLS `superadmin_bypass` usa `current_setting('app.user_role', true)` pero `app.user_role` NUNCA se configura. Los superadmins no pueden ver datos de otros tenants.

**Solución:** En `db.ts`, en el wrapper de `pool.query`, después de setear `app.tenant_id`, también setear `app.user_role`:

```typescript
// db.ts ~line 61
const setConfigSql = `SELECT set_config('app.tenant_id', $1, true), set_config('app.user_role', COALESCE($2, ''), true); `;

// Ajustar parámetros para pasar user_role también
```

Esto requiere modificar el wrapper para aceptar un segundo parámetro opcional. Simplifica: mejor que el middleware setee ambas variables de sesión.

### 1.3 Rate limiters en cadena

**Archivo:** `src/app.ts`

**Problema:** `loginLimiter`, `emailAuthLimiter`, y `authLimiter` se aplican al mismo endpoint. Atacante rota emails.

**Solución:** Reemplazar los 3 limiters por UNO solo:

```typescript
// Reemplazar ~line 199-241 con:
const loginLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,
  max: 10,
  standardHeaders: true,
  legacyHeaders: false,
  message: { error: 'Demasiados intentos. Intenta de nuevo en 15 minutos.' },
  keyGenerator: (req: Request) => {
    const email = (req.body?.email || '') as string;
    return `login:${req.ip}:${email}`;
  },
  handler: (req: Request, res: Response) => {
    logger.warn('Rate limit exceeded (login)', { email: req.body?.email, ip: req.ip });
    res.status(429).json({ error: 'Demasiados intentos. Intenta de nuevo en 15 minutos.' });
  },
});
```

Luego ELIMINAR `authLimiter`, `emailAuthLimiter`, y `loginLimiter` originales. Mantener solo `registerLimiter`, `refreshLimiter`, `forgotPasswordLimiter`, y `resetPasswordLimiter`.

## FASE 6: Simplificar Seguridad (día 5)

### 6.1 JWT: HS256 en lugar de RS256

**Archivo:** `src/shared/jwt.service.ts`

**Reemplazar** todo el contenido con una versión simple usando HMAC-SHA256:

```typescript
import jwt from 'jsonwebtoken';
import { getJWTSecret } from './jwt.js';

class SimpleJWTManager {
  sign(payload: Record<string, unknown>, options?: { expiresIn?: string }): string {
    return jwt.sign(payload, getJWTSecret(), {
      algorithm: 'HS256',
      expiresIn: options?.expiresIn || '15m',
    });
  }

  verify<T>(token: string): T | null {
    try {
      return jwt.verify(token, getJWTSecret(), { algorithms: ['HS256'] }) as T;
    } catch {
      return null;
    }
  }

  signInvite(payload: Record<string, unknown>, expiresIn?: string): string {
    return this.sign(payload, { expiresIn: expiresIn || '24h' });
  }

  getPublicJWKS() {
    return { keys: [] }; // HS256 no tiene JWKS
  }
}

export const jwtManager = new SimpleJWTManager();
export function getJWKS() { return jwtManager.getPublicJWKS(); }
```

**Eliminar:** `jwt.ts` (mantenerlo o simplificar a solo `getJWTSecret()`)
